Engineering approach

Built to show the whole picture.

DevOps is more than a list of tools. KumarStack connects infrastructure, application delivery and operational feedback into one project that can be explained, tested and improved.

Infrastructure is code

AWS resources are described with Terraform, making configuration reviewable, repeatable and easier to manage than manual setup.

Applications are packaged

Docker packages the website with a defined runtime; image tags make versions identifiable as they travel through the delivery workflow.

Operations are observable

Kubernetes health, Prometheus metrics, alert rules and Grafana dashboards provide a foundation for understanding service behaviour.

System architecture

One workflow. Multiple layers.

The project separates the infrastructure layer from the application and cluster layers. Each has a clear responsibility and a place in the repository.

KumarStack logical architecture

Source control → continuous delivery → runtime → feedback

Continuous delivery

From a code change to a release.

The intended application pipeline uses immutable commit-based image tags so a deployed version can be traced back to the source revision that produced it.

01

Commit and trigger

A change is pushed to the main branch and GitHub Actions starts the relevant workflow.

02

Build and publish

The workflow builds the Docker image from `docker-project/` and pushes a commit-SHA-tagged image to Docker Hub.

03

Deploy and verify

When EKS is available and access is configured, the workflow updates the Kubernetes Deployment and waits for rollout status.

Operational mindset

Think beyond “it works”.

The project includes the practical trade-offs that matter in cloud environments: repeatability, access control, recoverability and cost.

IaCReview before change

Use Terraform plans to understand proposed infrastructure changes before applying them.

OIDCShort-lived access

Use GitHub's identity federation for AWS workflows rather than adding long-lived access keys to source code.

SHATraceable images

Tag images with source revisions so releases can be related back to a code change.

CostUse resources deliberately

Shut down billable learning infrastructure when it's not needed and recreate it for focused tests.

About this project

A learning journey built into a working system.

I'm Pranay, and KumarStack is my practical DevOps and cloud engineering portfolio. I built it incrementally to understand how application code, cloud infrastructure, containers, orchestration and operational monitoring connect in an end-to-end delivery process.

The emphasis is on explaining engineering decisions, keeping infrastructure reproducible, automating routine work, and learning from deployment failures rather than hiding them.

The goal: demonstrate how I think through a system, how I automate it, and how I verify that a change has worked.
